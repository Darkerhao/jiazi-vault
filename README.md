# Keystill · 密序

**密钥有序，专注如常。** 原 Jiazi Vault，现以 Keystill 品牌持续迭代。

面向开发者的本地凭证保险库，集中管理账号密码、服务器、数据库、API Key、SSH 私钥和环境变量。

无需注册账号，无需部署服务端。凭证保存在本机，密码等敏感字段加密存储，日常使用支持离线操作。

[下载安装包](https://github.com/Darkerhao/jiazi-vault/releases) · [反馈问题](https://github.com/Darkerhao/jiazi-vault/issues) · [交付与验收记录](./DELIVERY.md)

## 功能

| 功能 | 说明 |
| --- | --- |
| 多类型凭证 | 登录账号、密码、服务器、数据库、API Key、SSH、安全笔记、自定义、环境变量集，共 9 种类型 |
| 项目与环境 | 按项目归档，区分 Development、Testing、Staging、Production、Other；新建凭证时可就地创建项目并自动选中，保留已填内容 |
| 搜索与整理 | 元数据关键词搜索、组合筛选、置顶、收藏夹、最近使用、分页列表；置顶凭证在活动列表和匹配搜索中优先，随后按匹配度、收藏和最近使用排序；快捷搜索可查看全部结果；多选批量改项目/环境、移入回收站和恢复，回收站保留 30 天 |
| 快速打开 | 带有 URL 的凭证可从列表、详情或快捷搜索直接用系统浏览器打开；API Key 的 Endpoint 可在详情和快捷搜索中打开；仅接受 http/https |
| 快捷复制 | 每行只保留一个按类型命名的复制入口（密码 / API Key / 私钥 / .env / 内容）；提示会显示复制内容和剪贴板清除时间 |
| 创建副本 | 在凭证详情中创建副本，带入字段、项目、环境和标签，编辑并保存后生成独立凭证 |
| 环境变量集 | 逐项编辑、显示和复制变量；导入 `.env` 时预览新增、变化与未变化变量，勾选确认替换，支持整组复制和导出 |
| 自定义字段 | 为凭证补充额外字段，支持重命名、多行内容、隐藏显示和一键复制 |
| 密码生成器 | 生成 8–128 位密码，可选字符类型、排除易混淆字符；在新建或编辑表单内预览并填入，也可从独立生成器保存到保险库 |
| 凭证健康 | 本地检查短密码、重复使用密码和 API Key 到期，按问题筛选并前往查看与修改 |
| 备份与迁移 | `.jvault` 手动/自动加密备份，验证预览后确认恢复，恢复前保留本机快照；JSON / CSV 可导出全部、单个项目或所选凭证 |
| 历史版本 | 最近 20 个加密历史版本，与当前保存内容逐字段比较新增、删除和修改；敏感值默认隐藏，支持确认恢复 |
| 桌面集成 | 开机自启、静默启动、关闭时最小化到托盘、全局快捷搜索、自动锁定、剪贴板定时清理、浅色 / 深色 / 跟随系统主题 |
| 系统快捷解锁 | 可选 Windows Hello 或 macOS Touch ID，默认关闭；设备不可用时使用主密码解锁 |

当前应用用于保存、整理、复制和打开凭证链接。尚未实现 SSH 连接、浏览器自动填充、云同步、团队共享和移动端。

侧栏独立的「关于」页显示当前版本，提供使用文档、项目主页、问题反馈和诊断信息复制入口；诊断信息仅包含应用版本、操作系统、架构及运行时版本，不包含凭证或本地路径。

桌面版启动时及运行期间每 6 小时自动检查正式新版，发现更新后在侧栏「关于」显示红点，折叠侧栏时仍可见。进入页面或阅读更新说明不会清除未安装更新的提示；检测不会自动下载或退出应用，网络失败时静默等待下次检测，也可手动重试。

在「关于 → 软件更新」中主动检查版本。配置了 Tauri 更新签名的正式 Windows、macOS 和 Linux AppImage 构建，支持下载、验证签名、确认未保存内容后安装；开发构建、未配置签名的构建及 Linux deb 使用官方下载页手动安装。更新只接受 Tauri 专用的 `tauri-updater.json` 和对应签名，不读取 Electron 的 `latest.yml`。从旧 Electron 版首次切换时，请先创建加密备份，再退出旧版并手动安装新版。

“近期更新”按版本展示最近 5 个正式版本的完整发布说明，支持查看单个版本详情或全部发布记录。自动检测、手动检查和读取发布说明会连接 GitHub，不上传保险库数据。

## 下载与安装

在 [GitHub Releases](https://github.com/Darkerhao/jiazi-vault/releases) 中选择对应平台和架构的附件。仓库配置的构建产物如下，实际可下载版本以发布页为准：

| 平台 | 架构 | 格式 |
| --- | --- | --- |
| Windows | x64 | `.exe` NSIS 安装包 |
| macOS | Intel x64 / Apple Silicon arm64 | `.dmg`，配置更新签名后另有 `.app.tar.gz` |
| Linux | x64 | `.AppImage`、`.deb` |

Windows 使用系统 WebView2。已安装 WebView2 的设备无需再次分发浏览器内核；缺少时，默认安装器联网安装 WebView2。安装完成后保险库日常操作可离线运行。应用包不包含 Chromium、Node.js 或 .NET 运行时。

保险库仍保存在原用户数据目录，更换设备请使用 `.jvault` 加密备份与恢复。上述格式描述当前源码，历史 Release 的架构与产物请以对应交付记录为准。

当前源码未配置正式 Windows 发布者证书和 Apple 公证；系统可能显示未知发布者或安全提示。Linux AppImage 需要执行权限及系统运行支持。更新包签名与系统代码签名不同，实际平台验收范围见 [DELIVERY.md](./DELIVERY.md)。

## 开始使用

1. 首次启动时设置并确认主密码，阅读安全须知后创建保险库。主密码至少 8 个字符，建议使用较长且独有的密码短语。
2. 在「项目」中建立项目，再通过「新建」选择凭证类型，填写内容并按需关联项目、环境和标签。
3. 将常用凭证置顶，或使用搜索、分类、收藏夹查找条目；可打开详情查看、编辑、复制字段，或直接打开凭证链接。
4. 在「设置」中调整自动锁定、剪贴板清除时间和主题；支持的设备还可启用系统快捷解锁。

成功使用一次 Windows Hello 或 Touch ID 解锁后，本机保险库会记住偏好，下次解锁默认展示系统认证入口，点击或按回车即可认证；也可切换为主密码。临时使用主密码不改变该偏好，系统认证不可用时自动显示主密码输入框。关闭快捷解锁、修改主密码或恢复备份会清除该偏好；偏好不随加密备份迁移。
5. 在「设置 → 加密备份与恢复」创建 `.jvault` 文件，或选择目录启用自动备份；建议保存到另一块磁盘。

**主密码没有找回或重置入口。备份也需要备份创建时的主密码才能恢复，请同时保管好密码和备份。**

在「设置 → 启动与窗口」调整以下本机偏好，设置自动保存，不随保险库备份迁移，恢复备份时保留：

- **开机自启**：默认关闭，开启后在登录电脑时启动。支持 Windows 和 macOS 的打包应用；开发环境和 Linux 禁用此项。macOS 需要系统允许登录项，签名与公证情况会影响可用性。Windows 便携版使用原始 EXE 路径，请保持文件位置不变。
- **静默启动**：默认关闭，开启后下次启动只在托盘运行，手动启动同样生效。首次使用及数据库损坏需要恢复时仍显示窗口。
- **关闭时最小化到托盘**：默认开启，关闭窗口会锁定保险库并隐藏；关闭此项后，关闭窗口直接退出应用。

通过托盘菜单或双击托盘图标可重新打开窗口；重复启动已运行的应用也会显示窗口。托盘菜单「退出」始终结束应用并清理本应用复制的内容。

| 操作 | Windows / Linux | macOS |
| --- | --- | --- |
| 全局唤起快捷搜索（默认，可修改或停用） | `Ctrl + Alt + K` | `⌘ + Alt + K` |
| 应用内快捷搜索 | `Ctrl + K` | `⌘ + K` |
| 快捷搜索中复制当前字段并关闭 | `Enter` / `Ctrl + Shift + C` | `Return` / `⌘ + Shift + C` |
| 快捷搜索中打开凭证 URL | `Ctrl + O` | `⌘ + O` |

| 新建凭证 | `Ctrl + N` | `⌘ + N` |
| 新建项目 | `Ctrl + Shift + N` | `⌘ + Shift + N` |
| 打开密码生成器 | `Ctrl + G` | `⌘ + G` |
| 锁定保险库 | `Ctrl + Shift + L` | `⌘ + Shift + L` |

应用内快捷键在解锁后使用，普通 Ctrl/Cmd+C 保留文本复制。从全局快捷键唤起快捷搜索时，复制或按 Esc 会收起窗口回到上一个应用；应用内 Ctrl K 打开的窗口保持显示。设置页可录入、保存或停用全局快捷键，注册冲突会就地提示。快捷键属于设备配置，不随备份迁移；正常恢复保留本机配置。

列表支持本页全选和跨页选择，切换筛选时清除选择。批量改项目/环境会保存各条凭证的历史版本，任一条失败则整批回滚；环境变量集不能清空环境。项目与凭证编辑在关闭或离开前会提醒未保存的修改，锁定仍会清除未保存内容。

### 环境变量集

新建「环境变量集」时需要选择环境，项目可选。支持逐项填写，也可从 UTF-8 `.env` 文件或粘贴文本导入，单次文件导入上限为 1 MiB。

导入会先预览并检查格式及文件内重复变量名，标记新增、值已变化和未变化。新增变量加入草稿，已有变量只有勾选「替换变量」后才更新；未勾选和文件未包含的变量保持原值。当前值和导入值默认隐藏，确认加入编辑器后仍需保存，取消或锁定不写入。导出支持 `.env.production` 等文件名，输出当前编辑值；不保留原注释和排版，也不执行命令、展开变量或修改系统环境变量。

### 凭证健康

侧栏「凭证健康」检查有效条目中少于 12 个字符的密码、完全相同的重复密码，以及 API Key 已过期、7 天内到期和无效日期。支持按问题筛选，点击「查看与修改」打开对应凭证，保存后回到健康页重新检查。回收站不参与检查，读取不增加使用记录。

密码仅在主进程本地检查，页面不接收密码或密码指纹，不联网查询泄漏库。这是基础检查，长度足够且未重复的密码仍可能容易猜测；不会将密码生成器的随机熵估算用于已有密码。

## 数据与安全

保险库使用 SQLite。Rust 明确沿用旧 Electron 的数据目录：Windows `%APPDATA%/jiazi-vault/vault.db`、macOS `~/Library/Application Support/jiazi-vault/vault.db`、Linux `$XDG_CONFIG_HOME/jiazi-vault/vault.db`（默认 `~/.config/jiazi-vault/vault.db`）。应用标识保持 `com.jiazi.vault`，数据库结构及 `.jvault` v1–v4 协议保持兼容。迁移过程不会自动搬移或重建个人保险库。

`KEYSTILL_DATA_DIR` 可指定独立数据目录，用于测试或明确选择其他保险库；桌面自动化始终使用仓库 `output/` 下的隔离目录。不要同时运行新旧底座操作同一保险库。

- 主密码通过 **Argon2id** 派生 256 位密钥，当前参数为 64 MiB 内存、3 次迭代、并行度 1，每个保险库使用随机盐。
- 密码、备注及 `fields` 中的数据（包括私钥、API Key、自定义字段、环境变量名和值）使用 **AES-256-GCM** 加密存储，每次加密使用随机 nonce。
- **数据库采用字段级加密。** 标题、类型、用户名、URL、主机、端口、标签、项目和环境等元数据以明文保存。搜索仅使用元数据，不检索密码、私钥、备注或环境变量内容。
- 主密钥仅由 Rust 持有，使用 zeroize 管理并在锁定时清除；Vue 通过类型化 Tauri 命令调用业务能力。仅允许本地主窗口，禁止外部导航和新窗口，文件、剪贴板和系统能力由 Rust 控制。
- 列表和快捷搜索的一键复制由 Rust 直接读取加密字段并写入剪贴板，主密码、私钥、API Key 等内容不经过页面。
- 凭证 URL 仅通过系统默认浏览器打开，应用内不嵌入或加载外部页面；仅接受 http/https 链接。
- 默认 15 分钟无操作后锁定，复制内容默认 15 秒后清除；两者均可在设置中调整。系统锁屏、休眠和关闭窗口会触发锁定；锁定或退出时也会清理仍属于本应用的剪贴板内容。
- 连续输错主密码会触发递增等待时间。修改主密码会在同一事务中重新加密现有条目、回收站和历史版本，完成后锁定保险库，并移除系统快捷解锁登记。

系统快捷解锁通过系统认证后读取设备保护的密钥：Windows 直接调用 Windows Hello 与 DPAPI，macOS 使用 LocalAuthentication 与 Keychain，Linux 暂不提供生物识别后端。旧 Electron 设备登记不跨底座复用，首次需主密码解锁后重新启用一次，界面会提示；这不改变主密码和保险库密文。设备登记不进入可移植备份，也不能视为同一操作系统账号下恶意进程的安全隔离。

相关实现见 [加密](./src-tauri/src/crypto.rs)、[条目](./src-tauri/src/items.rs)、[会话与命令](./src-tauri/src/vault.rs) 和 [系统认证](./src-tauri/src/biometric.rs)。

## 备份与数据交换

| 格式 | 用途 | 行为与限制 |
| --- | --- | --- |
| `.jvault` | 完整加密备份、设备迁移 | v4 包含凭证、历史版本、项目、回收站和偏好设置，备份数据整体加密；导出及恢复上限 256 MiB；仍可读取 v1/v2/v3 |
| JSON / CSV | 与其他工具交换条目 | 明文保存有效凭证；不包含回收站、设置及项目图标等信息；导入文件上限 64 MiB |
| `.env` | 环境变量集交换 | 明文复制或导出当前变量；文件导入上限 1 MiB，导入后需保存条目 |

恢复 `.jvault` 会**整体替换**当前凭证、历史版本、项目、回收站和偏好设置。覆盖正常保险库前会在本机 `recovery/` 目录生成一致性数据库快照，保存失败则停止覆盖。恢复窗口的「恢复来源」可选择这些快照，并使用快照创建时的原主密码恢复；每次恢复前继续保留当前库。快照沿用原数据库的字段级加密，元数据仍为明文，不代替异地加密备份。快照不自动清理，可在确认无需保留后自行管理 `recovery/` 文件。

恢复流程为：选择文件或本机快照 → 输入备份创建时的主密码 → 查看有效凭证、项目、回收站和历史版本数量 → 确认替换。预览及取消不修改当前库，锁定会使待恢复预览失效；最终恢复使用已验证的内容。恢复成功后使用所选备份或快照创建时的主密码解锁；修改主密码不会改变旧备份或快照的密码。数据库无法打开时，解锁页面提供恢复入口，原数据库文件会保留在数据目录的 `recovery/` 中。旧版本应用不能读取 v4 备份。

自动备份默认关闭，选择位置后创建独立文件夹并立即备份。应用解锁期间每分钟检查一次；有内容变化且距上次自动备份满 15 分钟时生成新文件，缺少上次文件时会重新生成。当前专用目录保留最近 10 份；新文件保存成功后才清理更旧文件，不清理手动备份或其他目录。锁定和退出时暂停，磁盘断开或写入失败时显示状态并可重试。停用或更换位置保留原文件。目录配置仅属于本设备，不进入可移植备份；正常恢复保留本设备选择的目录，并重置成功记录。

凭证详情的「历史版本」将所选旧版本（左侧）与当前保存内容（右侧）比较，标记新增、删除和修改，默认仅显示变化，取消勾选可查看全部内容。比较包含名称、类型、项目、环境、标签和所有内容字段；空值与不存在分别显示，字段值默认隐藏，切换版本或锁定后清除显示状态。恢复历史会将恢复前的当前内容保存为新版本，保留收藏、置顶和使用记录；历史项目已删除时恢复为未分配项目。回收站中可查看历史，需先恢复凭证才能恢复其版本；永久删除或满 30 天清理时级联删除历史。

JSON / CSV 导入先预览记录及格式错误，再确认追加有效条目。默认跳过与当前有效凭证或文件内前面记录内容完全相同的条目（忽略收藏、置顶和时间）；同名但内容不同仍新增，不覆盖原凭证。无效记录不会导入，预览不显示密码。取消或锁定后待导入内容失效。其他工具的专有格式需要先转换为本项目格式；字段说明见 [JSON / CSV 格式](./DELIVERY.md#json--csv-格式)，当前类型以 [contracts.ts](./src/types/contracts.ts) 为准。

设置页显示最近成功创建备份的时间。修改凭证、项目、偏好或主密码后会提示更新备份；查看和复制记录不触发提醒。自动备份检查最近文件是否存在，手动备份记录保存时间但不持续检查文件。恢复其他备份后需重新备份，启用自动备份时会在下次解锁检查后创建。建议将备份保存到另一块磁盘或外部设备，避免同盘故障同时损失原数据和备份。

凭证列表默认打开只读详情，点击“编辑凭证”才修改。顶部输入框只筛选当前凭证或项目列表，跨页面查找使用全局搜索（Ctrl K）。窄窗口侧栏自动折叠，编辑窗口内部滚动，底部保存按钮保持可见。

API Key 的过期时间使用 YYYY-MM-DD，并继续保存在加密字段中；所选日期当天按本地时区仍有效。列表支持已过期、7 天内到期及旧日期待修正筛选。到期提示依赖用户填写的日期，不会自动访问服务商确认或轮换密钥。

**JSON、CSV 和 `.env` 文件可能包含密码、私钥等明文内容。** 导出前应用会要求确认，这些文件需要自行妥善保管；完整备份使用 `.jvault`。

## 本地开发

技术栈：**Tauri 2 + Rust + Vue 3 + TypeScript + Vite + Naive UI + Pinia + SQLite**。界面与 Rust 通过单一类型化 IPC 边界通信，数据库、加密和桌面能力在 Rust 内实现，不使用 Node sidecar。

### 环境要求

- Node.js 24 与 pnpm 9.12.1，仅用于前端开发、打包和测试。
- Rust 1.90 或更新的稳定版，建议使用 rustup 管理。
- Windows：MSVC C++ 构建工具、Windows SDK 和 WebView2；无需 .NET SDK。
- macOS：Xcode Command Line Tools。
- Linux：WebKitGTK 4.1、GTK 3、AppIndicator 及相应开发包，具体安装命令见 CI。

```sh
pnpm install --frozen-lockfile
pnpm desktop:dev
```

开发服务器固定 `http://127.0.0.1:1420`。`pnpm dev` 只提供界面预览，完整凭据功能需要 Tauri；前端热更新，Rust 由 `tauri dev` 自动重编译。

### 常用命令

| 命令 | 说明 |
| --- | --- |
| `pnpm desktop:dev` | 启动 Tauri 桌面开发环境 |
| `pnpm typecheck` | Vue / TypeScript 类型检查 |
| `pnpm build` | 类型检查与前端生产构建 |
| `pnpm test` | Rust 回归、前端/Git 发布测试、原 Node 算法解密 Rust 备份 |
| `pnpm test:frontend` | 只运行前端纯工具和发布流程测试 |
| `pnpm test:desktop` | 构建并运行真实 Windows WebView2 桌面流程 |
| `pnpm test:package:win` | 对已构建的 NSIS 进行隔离安装、桌面验收及卸载 |
| `pnpm desktop:build` | 构建当前平台安装包，不发布 |
| `pnpm desktop:build:win` | 构建 Windows NSIS 安装包，不发布 |
| `pnpm audit:ci` | 检查前端依赖安全公告 |
| `pnpm brand:generate` | 使用 resvg 从品牌母版生成资源 |

前端输出 `dist/`，原生构建输出 `src-tauri/target/`，安装包位于对应 `release/bundle/` 子目录。`target/` 是开发构建缓存，不是分发目录。Windows 桌面测试通过 CDP 连接应用自己的 WebView2，不启动额外浏览器；设置 `KEYSTILL_TEST_EXE` 可检查指定的原生 EXE。

测试使用 `output/playwright/` 隔离数据，截图和报告也保存在该目录。安装器测试发现个人正式安装时会拒绝执行；应在干净测试机验收。系统锁屏/休眠消息模拟与真实物理操作分开记录；Windows Hello/Touch ID 的实际认证需要人工参与。

## 开发与发布流程

日常开发使用 `dev`；迁移在 `refactor/tauri-rust-migration` 中完成。`Check desktop changes` 在面向 `main` 的 PR 和手动触发时检查 Windows、macOS、Linux 源码；普通 `dev` 推送不触发。可在分支保护中将这些检查设为必需。

构建发布仍仅由 `main` 推送或手动触发：递增补丁版本，同步 `package.json`、`Cargo.toml`、`Cargo.lock`，创建版本标签并按提交生成说明；四个平台/架构构建全部成功后才发布，再把发布版本号写入 `dev`，不回合并业务代码。

自动更新需要 Secret `TAURI_SIGNING_PRIVATE_KEY`（可选密码 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`）和变量 `TAURI_UPDATER_PUBLIC_KEY`；公私钥必须成对配置。构建时公钥会同时写入 Tauri 更新器配置并编译进应用，缺少任一密钥仍只生成手动安装包，不会生成误导性的自动更新清单。已经安装的未签名旧版本没有更新公钥，需要最后手动安装一次首个签名版本，之后即可在应用内下载、校验、安装并自动重启。更新签名与 Windows 发布者证书、Apple Developer ID 签名/公证是不同事项。

本地构建不会发布或推送；自动化只操作隔离测试保险库。当前迁移的测量、验收和平台边界见 [DELIVERY.md](./DELIVERY.md)。
